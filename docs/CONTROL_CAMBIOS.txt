================================================================================
RESUMEN EJECUTIVO
================================================================================

Este proyecto implementa un sistema completo de comunicación segura y firma
digital de documentos de grado empresarial, migrado a arquitectura asíncrona
para máxima escalabilidad y rendimiento. El sistema utiliza RSA-2048 para
intercambio seguro de claves y AES-256-GCM con HMAC-SHA256 para cifrado rápido
de mensajes. La versión 6.0 agrega firma digital de documentos (TXT, PDF, ZIP),
servidor HTTP para subida de archivos, y documentación ejecutiva completa
(Resumen Ejecutivo, Project Charter, Presupuestos) para presentación con
stakeholders y usuarios no técnicos.

MEJORAS DE SEGURIDAD IMPLEMENTADAS
================================================================================

1. CIFRADO HÍBRIDO
   - RSA-2048: Cifrado asimétrico para intercambio seguro de claves AES
   - AES-256-GCM: Cifrado simétrico rápido para mensajes
   - Padding OAEP: Con SHA256 para RSA
   - Claves RSA generadas dinámicamente por conexión

2. INTERCAMBIO DE CLAVES
   - Intercambio automático de claves públicas RSA
   - Clave AES cifrada con RSA antes de transmitirse
   - Sin contraseñas compartidas requeridas
   - Cada conexión establece su propia clave AES

3. VERIFICACIÓN DE INTEGRIDAD
   - HMAC-SHA256: Verificación de integridad del payload cifrado
   - SHA256 Hash: Verificación adicional del mensaje descifrado
   - Logs incluyen hash SHA256 para auditoría

4. PROTOCOLO DE CIFRADO
   Capa de Transporte (v5.0):
   - SSL/TLS: Cifrado de transporte opcional
   - Certificados self-signed para desarrollo
   - Soporte para certificados de CA válida en producción
   
   Fase 1 - Intercambio de claves:
   - Cliente y servidor intercambian claves públicas RSA
   - Cliente genera clave AES y la cifra con RSA del servidor
   - Servidor descifra clave AES con su clave privada RSA
   
   Fase 2 - Cifrado de mensajes con validación SHA256 (v4.0):
   Estructura: [4 bytes: longitud] + [32 bytes: Hash SHA256] + [12 bytes: IV] + 
               [16 bytes: Tag GCM] + [32 bytes: HMAC] + [ciphertext]
   
   Validación:
   - Cliente calcula hash SHA256 del mensaje original
   - Cliente envía hash SHA256 junto con mensaje cifrado
   - Servidor extrae hash SHA256 recibido
   - Servidor descifra mensaje y calcula hash SHA256
   - Servidor compara hashes: si coinciden acepta, si no descarta

5. VARIABLES DE ENTORNO (v5.0)
   - Configuración centralizada en archivo .env
   - Sin valores hardcodeados en el código
   - HMAC_SALT configurable desde .env
   - SSL/TLS configurable desde .env
   - Fácil adaptación a diferentes entornos
   
   Fase 0 - Cifrado de Transporte SSL/TLS (v5.0):
   - Conexión TCP establecida
   - Handshake SSL/TLS (si está habilitado)
   - Canal de transporte cifrado con SSL/TLS
   - Sobre este canal se establece el cifrado híbrido (RSA + AES)

MÉTRICAS DE RENDIMIENTO
================================================================================

VERSIÓN 1.0 (Síncrona):
- Conexiones simultáneas: ~100-200 (limitado por threads)
- Memoria por conexión: ~1-2 MB
- Latencia: Variable según carga

VERSIÓN 2.0 (Asíncrona):
- Conexiones simultáneas: 1000+ (limitado por recursos del sistema)
- Memoria por conexión: ~50-100 KB
- Latencia: Consistente incluso bajo carga alta

MEJORA ESTIMADA:
- Escalabilidad: 5-10x más conexiones
- Eficiencia de memoria: 10-20x mejor
- Rendimiento: Mejor uso de CPU, menos overhead
